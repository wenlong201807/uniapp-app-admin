# F02 管理导航与权限展示基础技术方案

## 目标

对齐 RuoYi 的动态路由和权限展示思路，为管理端建立受服务端控制的导航目录。F02 只注册已实现的工作台、服务连接和管理员入口，不伪造用户、角色、部门等后续模块。

## 三端职责

- 服务端：在 `/api/v1/admin/routes` 返回编译期白名单中的导航记录；接口必须使用独立管理员 Bearer 会话。
- 管理端：登录后拉取目录，校验路径、名称、图标和权限字段，未知记录不渲染；直达未注册路径进入 404。
- 客户端：保持普通用户端，不加载 Web 管理组件；仅执行现有认证回归，避免管理员 token 与普通用户 token 混用。

## 安全与兼容

导航是展示数据，不能替代 API 授权。后续 F07 菜单和 F08 角色完成后，服务端将把静态目录替换为数据库菜单与权限集合。响应继续使用 `{ data: T }`，不改动普通 `/auth`、任务和媒体协议。

## 验收

1. 未登录访问管理路由重定向登录页。
2. 普通用户 token 请求 `/admin/routes` 返回 401。
3. 管理员登录后显示服务端目录。仅接口不存在（404/501）允许回退到现有基础页面；401 退出，403 和空权限目录不授予页面访问权；网络错误和 5xx 可重试。
4. 直接访问未知管理路径显示 404。
5. 管理端 `pnpm check && pnpm build`，服务端 `pnpm typecheck && pnpm build`，客户端 `pnpm check && pnpm test` 通过。

## 本次补齐

- 路径、名称、图标、权限必须同时匹配已编译的组件目录；忽略未知项、重复项和不支持的嵌套目录。登录 redirect 同样限定已注册路径。
- 登录、初始化、刷新和身份检查使用会话版本，退出立即清除本地身份，迟到响应不能恢复旧会话；并发刷新及身份检查共用一次请求。
- 每次保护路由导航检查 `/admin/auth/me`，已撤销会话在下次导航失效。网络失败保留内存会话，进入独立连接异常页面重试，不展示受保护页面。
- 导航加载共用一次请求，退出和身份切换使未完成加载失效；远程目录限制页面直达，但 API 权限最终由服务端验证。
- 登录表单防重复提交，成功后清空密码及 bootstrap token；服务端注销失败时仍进入登录页，并明确提示远程注销失败。

## 剩余完整范围

本方案目前落地基础导航和会话保护。功能总清单中的多标签/缓存、菜单搜索、主题/尺寸、全屏、细粒度权限按钮，以及服务端目录接口和三端联调仍未完成，不能把本次基础修复等同于 F02 全功能交付。
