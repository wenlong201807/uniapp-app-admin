## 实现范围

- 服务端新增独立 `AdminAccount` 表、`AdminAccountStatus` 和 Prisma 迁移。
- 服务端新增 `/api/v1/admin/auth/bootstrap`、`login`、`refresh`、`me`、`logout`。
- 管理员使用独立 Redis session key `admin:session:<id>` 和 `admin-access` JWT claim；普通用户 token 不可当作管理员 token。
- 首个管理员只能使用环境变量 `ADMIN_BOOTSTRAP_TOKEN` 创建，bootstrap 在已有管理员后拒绝；不设置固定默认账号/密码。
- 管理端新增登录页、内存会话、共享 refresh Promise、路由保护、退出按钮和移动宽度响应式样式。
- 管理端目前不持久化 token 或密码；关闭/刷新页面需重新登录，符合已确认的 D07 临时策略。

## 配置

服务端 `.env` 需临时设置随机的 `ADMIN_BOOTSTRAP_TOKEN`（至少 32 字符），并通过 bootstrap 创建独立管理员。创建后应删除或轮换该 token；不要提交 `.env`。

## 接口示例

```text
POST /api/v1/admin/auth/bootstrap
{ "email": "admin@example.com", "displayName": "系统管理员", "password": "<password>", "bootstrapToken": "<one-time-token>" }

POST /api/v1/admin/auth/login
{ "email": "admin@example.com", "password": "<password>" }
```

成功响应使用现有 `{ data: ... }` envelope，返回 `admin`、`accessToken`、`refreshToken`、`expiresIn` 和 `refreshExpiresIn`。`me/logout` 需要 `Authorization: Bearer <admin-access-token>`。

## 与参考项目的差异

参考项目使用其自身用户/RBAC 体系；本实现按用户确认使用独立管理员账号。角色、菜单、部门、数据范围和管理员 CRUD 将在后续独立功能分支实现。F01 不向客户端加入管理员入口。
