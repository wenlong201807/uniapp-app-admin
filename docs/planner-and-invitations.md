# 学习日程与单联系人邀请（P2-04）

经典场景：把学习任务加入本机日历，或主动选择朋友的邮箱邀请一起学习。

客户端云端任务点击“安排日程 / 邀请”，选择将来的日期、时间与时长，确认后写入日历（提前十分钟提醒）。再次保存更新本 App 事件；可删除本机日程。任务修改/删除不自动同步到日历，页面保留本机关联供手工清理。事件 ID 不上传服务器；关联按账号/服务地址/设备隔离。

邀请：主动选择系统联系人邮箱或手工填写，确认上传单个邮箱后生成七天代码。点击系统邮件编辑器，由用户确认发送，或复制代码自行发送。创建代码、系统编辑器打开都不代表已发送/送达。发送和接受需要验证账号邮箱；对方粘贴代码预览，确认后创建自己的独立任务副本。复制只包含任务标题与说明，没有位置/媒体/共享修改权限；重复接受不产生重复任务。

系统联系人选择器仅返回选中的邮箱，不申请 READ_CONTACTS 或读取整本通讯录。邮箱只在组件内存保存、确认后传给服务器；服务器只存 HMAC 匹配摘要。邀请代码只存散列，列表/管理端/审计不展示收件邮箱、匹配摘要或代码。复制会进入系统剪贴板。

管理端 `/task-invitations` 查看创建人、任务、状态、到期和接受时间，可撤销未接受邀请；不能通过撤销删除收件人已接受副本。无本机日历/通讯录查看能力。

Android 须合入服务端 `artifacts/planner-android/moment-planner.jar`/DEX，自定义原生基座或包包含 READ_CALENDAR/WRITE_CALENDAR。iOS 嵌入并签名 `artifacts/planner-ios/MomentPlanner.framework`，链接 EventKit/Contacts/ContactsUI/MessageUI，配置旧版与 iOS 17+ 日历用途说明。仅编译 uni-app 资源不包含原生类。鸿蒙原生日历、联系人和邮件 Kit 桥接仍待办，当前明确不支持；手工邮箱与邀请服务流程可用。

真机待办：原生包集成、三系统权限拒绝/取消、时区/夏令时/系统通知、日历外部修改/删除/账号变更、联系人的多邮箱/无邮箱、选择器 Activity 切换、离线和邮件取消/投递。系统日历可能同步到用户日历账号；极端崩溃/重装可能失去关联，需在系统日历清理。详见服务端 `docs/phase-fourteen.md`。
